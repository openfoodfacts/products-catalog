## Documentation

We use diataxis framework meaning documentation is separated between tutorials, how-tos, explanations and reference documentation.
Each file in docs start with a specific prefix for each category (the document title also start with this word): `tutorial-`, `how-to-`, `explain-` and `reference`.

In the code, comments are mandatory of modules / functions / etc., to summarize several lines of codes (help human reader), or to explain the how and the why or less common code patterns.

In comments and in markdown,
split lines at a point that semantically make sense.
This allow for better git revisions in case of modifications.
